# Enforcement matrix

Where each check runs and what it does on failure. **Fails** = a deterministic failure of the named command.
**Detects** = a tool flags it, a person or agent confirms. **Manual** = only a person can verify it.

Runs: `test` = `npm test` (so `npm run validate` and CI); `lint` = `npm run lint` (validate, CI); `browser` =
`npm run quality` / `npm run test:browser` (Chromium, one page per template) and CI (Chromium, Firefox, WebKit);
`audit` = `npm run quality -- --audit` (every page, three engines, `npm audit`); `ci` = `.github/workflows/pages.yml`.

## Exceptions and budgets

`tests/web-quality.json` is the baseline. Each exception is `check` + one `rule` + a `page` regex + optional `target`
regex + `reason`; the gate rejects blanket patterns and short reasons, and fails on an exception that no longer matches
(static checks always; browser checks for the pages that run covered). Budget overrides are ratchets with a reason.

## Not automated, by design

- A pre-commit hook: the repo has none and `npm run validate` is the documented pre-commit step.
- A Claude Code hook that runs browsers on every edit: too slow. `.claude/settings.json` has a PostToolUse hook that
  only reminds once per session, after the first site-file edit, to run `npm run quality`.
- Lighthouse CI: lab scores would duplicate the budgets and CLS check and cannot speak for the field.
