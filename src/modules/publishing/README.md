# publishing

Publishing owns YouTube only: uploads, release approvals, scheduling, go-live, read-back and verification, recorded in the per-story ledger. Social (X and others) is a separate Milestone 2 module and never part of this one.

- Inputs: `video/review/review.json` and the review package of the story (the build report through shared `build-report`), `video/upload-session.json`.
- Outputs: `publish.json` per story: `events` are written only by the CLI, `metadata` may be hand-edited and is validated at build.
- CLI: `npm run publish -- <verb> <topic> <story-id>` (`cli.ts`). Hand verbs: `show`, `uploaded`, `approve`, `accept-draft` (the draft acceptance `video final` records, run by it as a child; refused on an output already approved for publication: live, scheduled, or its release build approved), `thumbnail`, `scheduled`, `published`, `updated`, `failed`, `unpublished`, `retracted`, `add`. API verbs: `auth`, `upload` (always private), `push`, `go-live`, `sync`, `verify`.
- Draft acceptance: `recordApproved({ accepted: true, build })` writes the same `approved` event as an approval, but only for a provable draft: the draft packaged on disk, or the draft the release build on disk replaced (`replaces` in its build report, written by video QA). A release sha, a stale or unknown sha and a missing `build` are refused. An accepted build is only ever a draft, and every public path (a public upload, `scheduled`, `published`, `go-live`) refuses a draft, so an acceptance never authorises publication.
- Files: `publish.ts` (ledger and verbs), `uploader.ts` (API verbs), `youtube.ts` (the one API client), `verify.ts` (read-back checks), `outputs.ts` (the public video view of a ledger).
- Inspect: no; the board reads `outputStates` and the other names `index.ts` exports.
- Public API (`index.ts`): ledger readers and types, `outputStates`, `currentBuild`, `mainOutput`, the `record*` writes the review page and video use, `storyOutputs`, `seekUrl`, `uploadProblem`.
- Read API (read-only, nothing written; listed under `publishing` in `tests/boundaries.json`): `loadLedger(topic, storyId)` reads `publish.json` and returns the validated ledger or null; `mainOutput(ledger)` is the video's main output id, computed from a ledger already read; `uploadProblem(metadata)` is the YouTube limits check on title, description and tags, a pure function; `storyOutputs(topic, storyId, root)` is a story's live video and Shorts from its ledger and review package; `currentBuild(dir)` reads the packaged build (mp4 sha and draft or release status) from `video/review/review.json`, or null.
- Shared: `Refusal` lives in `src/shared/refusal.ts`; the stories file is read through shared io.
