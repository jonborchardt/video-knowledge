# video

Video owns the media of a story: narration, the timeline, the Remotion render (scene chunks, the end card), the soundtrack mix, QA and the render check of its bespoke graphics. Packaging owns the review package made from it; publishing owns the ledger.

- Inputs: `video/render.json` (scenes, voice, cues, kinds, options), `storyboard.json`, `script.json` and `release.json` through `loadSegment`, the narration cache `video/narration/`, `video/music.json` over `music/<composition>/`, the institution's kit from `brand/` (staged into `video/brand/`), `video/visual-review.json`.
- Outputs: `video/narration.json`, `timeline.json`, `segment.mp4` (and the chunks in `scenes/`), `build-report.json`, `build-report.md`, `mix.json`, `render-check.json`, `frames/`, `contact-sheet.png`. Media is never committed.
- Briefs: `briefs/graphics.md` (a bespoke graphic), `briefs/visual-review.md` (its independent review), `briefs/video-fix.md` (a render check or QA failure), `briefs/strudel-bench.md` (the soundtrack handoff).
- CLI: `npm run video -- init|check|frames|narrate|timeline|render|qa|spike|package|final|preview` (`cli.ts`; `package` spawns packaging's CLI), `npm run music -- cues|import|render|show` (`cli-music.ts`).
- Inspect: no; the board reads `BuildSummary` (`src/shared/build-report.ts`) and `render-check.json` through the read API.
- Read API (`index.ts`, read-only, nothing written; listed under `video` in `tests/boundaries.json`): `loadSegment(topic, storyId)` reads the script, storyboard, release and render.json into a `Segment`; `RENDER_CHECK` (the file name), `RenderCheckSummary`, `renderCheckProblems` (a pure check over a read render check); `VIDEO_FILES` and `videoDir` (paths); the types `Timeline`, `Segment` and `BuildReport`. The board also takes `renderCheckStale` and `renderConfigSha` from `index.ts`.
- Consumes: publishing's `currentBuild` (read API); publishing through its CLI (`final` records the draft it accepted with `npm run publish -- accept-draft <topic> <story> --by <approver> --build <draft sha>`, `acceptDraftViaCli` in `final.ts`: once with `--dry-run` before narration, so an output already approved for publication refuses before the paid render, then for real after QA and package, so the release build's report already names the draft in `replaces`; only a draft voice is accepted); the board through its CLI (`final` runs the board CLI as a child, `board next <topic> <story> --json` under the repo's tsx, `boardViaCli` in `final.ts`).
- Fingerprint: `componentVersion` (`render.ts`) hashes normalised sources (type-only imports dropped, value imports followed), so a move of the tree or of a type's home never moves a graphic key or a chunk key. `video/key-migration.json` beside each visual review records the one-time key migration.
- Browser-safe (no node imports): `remotion/`, `bespoke/`, `types.ts`, `kinds.ts`, `words.ts`, `chart.ts`, `cues.ts`, `excerpt.ts`.

## Target duration

A story's optional `targetDurationSeconds` (set in `story-review.json`, carried by the package) proportions this stage by band through `src/shared/duration.ts`; the module's correctness checks do not change with it. See the Script rule in CLAUDE.md.

`briefs/draft-review.md` (Milestone 2, spec §7.3) is the draft-review agent's brief: a fresh agent that did not make the video judges the draft from the review package, the frames, the captions and the storyboard, and writes `video/draft-review.json` (`{ key, verdict, notes, reviewer, session, date }`); the runner records its verdict beside the person's under `review.draft: shadow` and acts on it under `agent`. `final` accepts the agent's actor only under that policy, through `publish -- accept-draft`. The Azure key boundary of `final` is unchanged: the CLI forgets `AZURE_*` right after `.env` and only the per-sentence worker holds it (`tests/final-env.test.ts`).
