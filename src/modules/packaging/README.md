# packaging

Packaging owns the review package of a rendered video: titles, descriptions, captions, chapters, the placement of the calls to action in the description, and the release metadata. Video owns the media and QA; the YouTube limits check (`uploadProblem`) is publishing's and packaging only calls it.

- Inputs: `video/timeline.json`, `video/build-report.json`, `video/segment.mp4`, the script's release files (through `loadSegment`), `cta.json`, and for a Short the parent's `publish.json`.
- Outputs: `video/review/*`: `review.json`, `description.txt`, `README.md`, `checklist.md`, `captions.en.srt`, `links.json`, `thumbnail.png`, `build-report.md` and the mp4 copy; for a release build also `release-manifest.json` (`manifest.ts`, spec 7.2: every output of the release group with its media, metadata and assets, the article's release sha, the public URLs, the calls to action with paid ones numbered, the institution, the composed X post, and `releaseSha` over what a person approves), removed when a draft is packaged; a Short's package rewrites its parent's manifest, and `cli.ts manifest <topic> <story-id>` rewrites it from the files without media (the article lock calls it).
- CLI: `tsx src/modules/packaging/cli.ts package <topic> <story-id>` (`cli.ts`), reached as `npm run video -- package`, which `video -- final` runs too. A Short is also recorded as the output `short:<slug>` in its parent's ledger by spawning the publish CLI (`publish -- add`), never by importing a write.
- Inspect: no; the board reads the package through publishing's `currentBuild`.
- Public API (`index.ts`): `descriptionLinks`, `renderDescription`, `keywordsOf` (the YouTube tags: the institution and the inquiry only, never a question or a claim; a person's own tags in `publish.json` replace them), `assertWithinLimits` and their types. Chapters (`chapters()` in `package.ts`) are titled by `chapterTitle` (`src/shared/sentences.ts`: a question section's question, else a plain name a viewer can read, never `Hook` or `Close`); a `render.json` chapter title that is exactly the old section default is read as none, so a video initialised before that change needs no edit and no render.
- Read API: `loadManifest(topic, storyId, root)` (the manifest on disk, or null) and `manifestPath`, for orchestration; publishing reads the file through `src/shared/io.ts` (`MANIFEST_FILE`) and the shared `ReleaseManifest` type, never through this module.
- Consumes: publishing's read API (`loadLedger`, `mainOutput`, `uploadProblem`); website's read API (`contentGraph`, `matterPath`, `storyNode`, `loadCta`, `resolveCtas`, `ctaPath`, `publicUrlsOf`); article's (`loadArticleRelease`, `ArticleRelease`); `src/shared/social-text.ts` (`composePost`, the template the social module posts with); video's `loadSegment` and the `Timeline`, `BuildReport` and `VIDEO_FILES` types and paths (its read API).
- Shared: `REVIEW_DIR` (the folder name under `video/`) lives in `src/shared/io.ts`.
