# social

X posts about a story's live outputs from the owning institution's account (Milestone 2, phase 3; spec §4.5's X row, §15). Optional per institution: an institution without an X handle or keys is "not configured", never a halt. Separate from publishing (YouTube): no coupling, no shared framework; the orchestration's launch probe runs `post` after the deploy is confirmed.

- Inputs: `publish.json` (through publishing's read API, `storyOutputs`: only a live output is posted about), `src/config/site.ts` (`Commission.x`, the public handle once a person created the account), `.env` (`X_<KEY>_API_KEY`, `_API_SECRET`, `_ACCESS_TOKEN`, `_ACCESS_SECRET`, `_USER_ID`; `X_<KEY>_HANDLE` names a test account beside its keys when the commission has no public handle yet).
- Output: `topics/<topic>/scripts/<slug>/social.json` (`SocialFile`: per output, every post with its `textSha`, status `posting` (the intent, written before the call), `posted` (the id and URL) or `failed`).
- CLI: `npm run social -- show|compose|post <topic> <story-id> [--output <id>] [--dry-run]` (`cli.ts`). `post` refuses (exit 2) while `automation.json` `enabled.social` is off or the output is not live, exits 0 printing `not configured` without a handle or keys, and never posts the same text twice: a `posting` record without an id (a crash after the call) is reconciled from the account's recent posts before any repeat; X's duplicate refusal is recorded as posted with no id. `X_FAKE=<file>` (tests only) swaps the network for a recording client.
- Text: the shared `composePost(title, url, disclosure)` of `src/shared/social-text.ts`, the same words the release manifest showed the person (`<title>\n\n<url>\n\n<disclosure>`, within 280 counting a URL as 23, the disclosure once).
- Read API (listed under `social` in `tests/boundaries.json`): `loadSocial`, `socialPath`, `inspectPosts(topic, storyId)` (`Inspection`: `missing` no file, `invalid` a failed post, `stale` a live output without a post for a configured institution, `ready`).
- `x.ts`: `xClient(creds, fetchFn)` (OAuth 1.0a user context, HMAC-SHA1 with `node:crypto`; `POST /2/tweets`, `GET /2/users/:id/tweets`; 429 and 5xx retryable, a 403 duplicate marked), `credsFor(key, env)`. The signature is tested against the example in X's developer documentation ("Creating a signature").
- Tests: `tests/{compose,x,cli}.test.ts`.
