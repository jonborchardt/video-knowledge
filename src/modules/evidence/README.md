# evidence

Evidence gathers and judges claims for a topic it is given; proposing or evaluating new topics is topic discovery (`src/modules/topic-discovery/`) and never evidence's job.

- Inputs: `topics/<topic>/store/**` through the watcher, `sources/*.txt`, `data/*`, `site.json`, the agent batches `h*.json` (extraction) and `sv_*.json` (study verdicts).
- Outputs: `report.json`, `applicability.json` (only `record-sources` writes it), and `public-record.json` through shared `public-record.ts`.
- Briefs: `briefs/extract.md`, `briefs/sources.md`, `briefs/evidence.md`; Milestone 2 phase 5: `briefs/collect.md` (the source lists; role `collect`, shell `evidence -- search` and `fetch-doc` only), `briefs/studies.md` (study documents saved through `fetch-doc`; role `collect`), `briefs/merge.md` (semantic merges and distinct claims after `dedupe`; role `extraction`, no shell), `briefs/revision-note.md` (a note per revised finding, written by the runner through `report -- note`; role `notes`, writes nothing).
- CLI: `npm run report [-- seed|note]` (`cli-report.ts`), `record`, `record-sources`, `watcher`, `merge-claims` (the `.mjs` files load `batches.ts` and `cited.ts` by `.ts` path under plain node); `npm run evidence -- search|fetch-doc|lists|groups|check-batch|dedupe|check-merges|collide|thin` (`cli-research.ts`, the deterministic research verbs of spec 5.2: `search.ts` parses a YouTube results page's `ytInitialData`; `groups.ts` splits the watcher's extract entries by transcript size; `dedupe.ts` turns exact cross-file duplicate new claims into `n2`; `collide.ts` finds near-duplicates with the watcher's own `similarity` loaded from its checkout by file URL (the same formula local as the fallback) and `--resolve` merges what an agent left open; `fetch-doc.ts` saves one document as text under `sources/` with a `Source:` header, https only, a bare `.txt` name, `pdftotext -layout` or a tag-stripper; `thin.ts` says which of `topics.minSources`, `minStudies`, `minDecided` is short; `lists`, `check-batch` and `check-merges` are the validators the runner runs after the collect, extract and merge agents).
- Maintenance (Milestone 2 phase 6): `maintenance.ts` (`topics/<topic>/maintenance.json`: `lastScan`, the scans; `scanDue(file, everyDays, now)`; written only by `npm run evidence -- scanned`), `briefs/new-sources.md` (the scan agent: evidence published since the last scan, saved through `fetch-doc`, judged into `work/sv_scan-<date>.json`; role `collect`).
- Inspect: no.
- Public API (`index.ts`): the topic views and loaders (`loadTopic`, `topicNames`, `publicTopicNames`, `VAL`), `corpusOf`, datasets (`loadDatasets`, `dataRef`, `datasetCsv`), the finding and verdict labels, and the view types.
- Read API (listed under `evidence` in `tests/boundaries.json`; loaders, a table and pure projections): `loadTopic`, `topicNames`, `publicTopicNames`, `VAL`, `Topic`, `corpusOf`, `loadDatasets`, `dataRef`, `findingLabel`; the view types `ClaimView`, `DataTable`, `FindingLabel`, `SourceClaimView`, `SourceView`, `SurpriseView`, `Verdict`; `FINDING_LABELS` and `FINDING_TEXT`, constant tables of the four labels and their text; `labelCounts(claims)`, each label's count, pure; `verdictLabel(verdict, confidence)`, a verdict's wording and colour, pure; `datasetCsv(table)`, a dataset as CSV text, pure.
- Consumes: publishing's `storyOutputs` (`live-claims.ts`: which claims have a live video, pinned equal to the content graph by `tests/live-claims-equivalence.test.ts`) and storyboard's `pointProblems`.
