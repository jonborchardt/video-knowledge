# topic-discovery

Topic proposals per institution (Milestone 2, phase 4; spec §5.1): an agent proposes, an independent agent reviews, code validates and ranks, weak proposals are parked with the reason, and only a person approves or rejects. Nothing here researches: no fetch, no store write, no file under `topics/`. The module never becomes a second evidence implementation (`src/modules/README.md`, boundary 1).

- Files: `proposals/<slug>.json` (`Proposal`, `src/shared/types.ts`: the question, rationale, fit, 5 or more checkable claims as the public makes them, 8 or more popular sources, 4 or more studies or datasets, the overlap with existing topics and stories, five scores, `status` `proposed | approved | rejected | parked`, the decision and the batch it went out in) and `proposals/<slug>.review.json` (`ProposalReview`: the reviewer's `fit`, a verdict of 40 words or more a person can check, concerns, its own five scores). Both committed.
- `proposals.ts`: `validateProposal(p, existing, a.topics)` (schema; slug `^[a-z0-9-]{3,40}$` and not an existing topic; the institution a commission; 5 or more claims of 6 or more words with a verb, no two the same after normalisation; 8 or more `https` sources and 4 or more studies with no duplicate URL; scores in [0, 1] and not all equal; the question not an existing story's nor another proposal's; rationale and fit 40 words or more), `validateReview(r, p)`, `rank(proposed, a.topics)` (each side's overall `(2 evidence + 2 checkability + depth + fit + novelty) / 7`; the ranked overall their mean; `weak` when either side is under `topics.minOverall` or the reviewer's `fit` is false; `unreviewed` last and never batched), `inspectProposal(slug, root)` (`Inspection`: `missing` no file or no review (`unreviewed`), `invalid` with either file's problems, `ready` with the code `proposed | weak | approved | rejected | parked`, `stale` when approved and researched: `topics/<slug>/stories.json` has a ready story), `loadProposals(root)`, `existingOf(root, except?)`.
- Read API (listed under `topic-discovery` in `tests/boundaries.json`): `claimedBy` (the commission a site.ts source claims a topic for; the research board reads it from disk), `loadProposals`, `proposalPath`, `reviewPath`, `inspectProposal`, `rank`, `researched`, the types `Proposed` and `Ranked`.
- The adversarial fixture `tests/fixtures/proposals/padded.json` (criterion 16) is invalid by code before any person sees it; `good.json` and `good.review.json` are the valid pair the tests build on.
- Tests: `tests/proposals.test.ts`, `tests/claim.test.ts`.
