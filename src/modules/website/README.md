# website

Website owns rendering, the content graph and building and deploying the site. It renders `article-release.json` and never decides whether a finding needs a correction (article owns corrections and reaffirmations). The Astro folders (`src/pages`, `components`, `layouts`, `styles`, `admin`, `tools`) and `astro.config.mjs` are part of it and stay where Astro needs them; they import `site-graph.ts` directly.

- Inputs: `report.json`, `stories.json`, `public-record.json`, `article-release.json`, `publish.json`, `video/review/*`, `cta.json`, the datasets.
- Outputs: the built site (`dist/`, with `feed.xml`, `llms.txt` and each matter's `index.md`: `src/pages/feed.xml.ts`, `llms.txt.ts` and `[topic]/[story]/index.md.ts` gather the data and `syndication.ts` renders it (`feedXml`: the public first questions, newest first; `llmsTxt`: every public matter, follow-ups included, under its inquiry; `matterMarkdown`); `matter.ts` (`matterModel`) is the one loader the HTML matter page and its Markdown copy share, so they cannot drift; fixture topics stay out of all three), `public-urls.json`, `.web-quality/`.
- Briefs: `briefs/cta.md`.
- CLIs: `npm run links -- freeze|check|cta|cta approve|live` (`cli-links.ts`), `npm run quality` (`cli-quality.ts`), `npm run rehearse` (`cli-rehearse.ts`). `live <topic> <story-id>` (`live.ts`, phase 3) is the deploy confirmation: one request to the story's matter page on the public site, `RESULT: LIVE` when it answers 200, carries the live video's id and the path is in `public-urls.json`, else `RESULT: NOT LIVE (<why>)` and exit 1; the id it looks for is the live video's, else the releasing one's (decided `ok`, deployed before it goes public); `liveCheck(topic, storyId, fetchFn, root, { baseUrl, expectAbsent, frozen })` is the read API the tick's probe calls (a fixture's negative probe on the production host, its positive probe on the preview host). The page's `<title>` is the released article's `seoTitle` alone (the site adds no suffix), else the story title with the commission's name; `Base.astro` takes `markdown` (the matter's `index.md`, announced `rel="alternate"`) and `article` (`og:type` article with its published and modified times); every page announces the feed.
- Inspect: no.
- Public API (`index.ts`): the node-safe surface only (nothing reads `import.meta.env`): content graph, calls to action, SEO, review page model and job, rehearsal helpers. `site-graph.ts`, `matter.ts` and `syndication.ts` are Astro-only and not exported; the pages import them by path.
- Read API (read-only, nothing written; listed under `website` in `tests/boundaries.json`): `contentGraph(root, topics, view, assumeLive)` builds the graph from the topic files (a story is public with a live or releasing video, when assumed live, or when its matter path is frozen in `public-urls.json`, read once per build; `Graph.view` records the view, and `isPreview` marks a public story without a video only outside the live view: in the live view it is a page kept for its frozen URL); `storyNode(topic, storyId)` is a story's node id; `matterPath(topic, story)` is its site path; `loadCta(topic, storyId)` reads `cta.json`; `resolveCtas(file, graph, story)` checks it against the graph; `ctaPath(topic, storyId)` is its file path; type `CtaType`.
- Consumes: article's `loadArticleRelease`, `articleView`, `releaseFigureDraws`; publishing's ledger and output readers (`storyOutputs`, with `releasing`); the shared public record; evidence (`loadTopic`, `publicTopicNames`, `loadDatasets`, `dataRef` through its `index.ts`), stories and shorts through their read APIs. Website never imports packaging.

Read API additions (Milestone 2): `publicUrlsOf(topic, storyId, root)` is the absolute matter, article and data URLs a story's release will have, pure over the graph with the story assumed live. `resolveCtas` lists every paid link of `cta.json` under `commercial` (`ctaId`, approved or not): an unapproved one is dropped from the description and shown numbered in the release manifest for the person's `PAID OK`; an `automated:` or placeholder `approvedBy` is still a file problem. `approveCommercial(topic, storyId, id, by)` (`npm run links -- cta approve <topic> <story-id> <id> --by <name>`, phase 3) writes a person's approval into the matching entry once; publishing's `decide` runs it as a child for each `PAID OK` link.
