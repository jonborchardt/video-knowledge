# Orchestrator: harden the script pipeline and lock the MLM package

> **For agentic workers:** This file sequences five plans. Execute each plan with superpowers:executing-plans (native) or superpowers:subagent-driven-development, in order, and do not start a plan until the previous plan's exit check is green. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run Plans 1 to 5 one after another without human intervention, so that the MLM script and storyboard end up locked, committed, merged, tested against the real artifacts, and tagged as the rendering baseline. The only stops are genuine failures listed under Halting conditions.

**Spec:** `docs/superpowers/specs/2026-10-17-hardening-spec.md` (Jon's brief and the deferred list). Background: `docs/superpowers/specs/2026-10-17-audit-report.md`.

**Plans, in order:**

| # | Plan file | Exit criterion (from the spec) | Approval |
|---|---|---|---|
| 1 | `2026-10-17-01-validation-loopholes.md` | Invented numbers, unsupported quotations and unverifiable speaker attributions fail validation | none |
| 2 | `2026-10-17-02-reproducible-evidence.md` | Changing a cited document invalidates approvals; a clean checkout can inspect the MLM evidence | none |
| 3 | `2026-10-17-03-machine-readable-storyboard.md` | A renderer can read a scene's narration, timing, type, chart data and citations without parsing prose | none |
| 4 | `2026-10-17-04-mlm-revalidate-and-lock.md` | No blocking facts, warnings dispositioned, approval recorded in `release.json` | the executing agent runs `lock` after the independent reviewer passes revision 3 |
| 5 | `2026-10-17-05-commit-test-baseline.md` | Green build from a clean checkout; PR merged; tag `mlm-script-v1` | the executing agent merges when CI is green |

## Global rules for every plan

- Work on branch `script-stage` (create it from the current working tree before Plan 1: `git checkout -b script-stage`, then make the first commit the already-finished script stage: `git add -A && git commit -m "feat: script stage (evidence package, validator, storyboard, MLM package)"` with the attribution line). The existing uncommitted work is the starting point; do not discard it.
- Before each plan, read the plan file in full and the two spec files. Each plan's "Global Constraints" and "Review Focus" sections are binding.
- Run `npm run validate` at the end of every task; a red task is fixed in place before the next task.
- Never hand-edit `<topic>/store/` or `stories.json`; derived script artifacts (`validation.json`, `script.md`, `storyboard.md`, `review.md`, the filled `storyboard.json`) are regenerated by the CLI, never edited.
- Writer and reviewer are different agents. When a plan says "reviewer agent", spawn a fresh subagent with `scripts/briefs/script-review.md`; when it says "writer agent", that may be the executing session following `scripts/briefs/script.md`.
- Shell on this machine (Windows, Git Bash through the harness): keep commands ASCII-only; a heredoc containing `${...}` or backticks breaks under the harness wrapper, so write multi-line edit scripts (Python or Node) to a scratch file with the Write tool and run them with `python3 -I <file>` or `node <file>`; use the Edit tool for TypeScript changes.
- Facts about the data that a fresh session will not know: only recorded verdict passages are citable (a new passage needs a verdict via `record-sources`, which needs the watcher checkout); the story audit keeps one verdict per document per claim, newest first, so recording a second passage from a document supersedes the first in `stories.json` while old cites stay valid for scripts; the Taylor PDF text is two-column and interleaved, so quotations from it must sit on one line; the FTC report's year 2024 is in no cited passage and AARP's 2018 is only in a page header inside L376-L392; the FTC blog (`ftc-mlm-report-blog.txt`) summarises the FTC report and is marked `sameStudy` in `get-rich-quick/site.json`.
- Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Do not do (deferred by Jon)

Fully automatic Claude orchestration; more sophisticated story ranking; a general-purpose visual component architecture; deterministic detection of every causal or semantic error (semantic review stays the enforcement layer); a fancy Astro editorial UI; generalized media asset management; timestamp-churn and cosmetic cleanup as a milestone.

- [ ] **Step 6: Final report.** One message to the user: the five exit checks with their observed output, the final `review.md` summary table, the tag, and the three items the audit left for the rendering stage (numeral pronunciation, asset production, SSML or TTS script export).

## Halting conditions

There are no approval stops. Stop and report only when: an exit check fails twice after a fix attempt; a plan would need a change the deferred list forbids; the PR cannot be merged because of branch protection or a red CI run that two fix attempts did not clear; or a step would modify the store other than through `record-sources`. A script that still blocks at revision 3 is not a halt: Plan 4 records the blockers and Plan 5 ships the unlocked package without the tag, and the final report says so in its first line.
