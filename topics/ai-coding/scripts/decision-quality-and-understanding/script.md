# Is AI-Written Code Harder to Maintain?

## Hook

If an AI writes the code today, who pays for it when somebody has to change it next year? One research team stopped guessing and ran a randomised trial: code written with or without AI, then changed by hand. [s02 ok]

## Setup

The worry has a familiar shape: one study collected in a review of the research warns that code built up through conversation often "lacks cohesive structure", which makes later maintenance harder. [s03 ok] And on security, the Razorwire Cybersecurity channel put it bluntly: "46% of AI generated code is reportedly uh contain some form of security weakness". [s04 ok]

## Investigation

So what happened in that trial when people had to change code an AI had helped write? On speed, nothing reliable: their completion times were consistent with no effect at all. [s06 ok] The authors are careful about what that means: any difference was at most small, and highly uncertain, which is not the same as proof there is none. [s07 ok] On quality, the code's health score after the changes showed no reliable difference either, and test coverage was essentially identical. [s08 ok] A second, Bayesian analysis even hinted at a small gain in code health when the original was written with AI by someone who uses it habitually. [s09 ok] Dave Farley, talking about the study, summed it up: "The AI didn't make it any better and it didn't make it any worse." [s10 ok] So where does the debt fear get its evidence? Partly from surveys: one study measured maintainability and technical debt through its respondents' answers to questionnaire scales, and AI use went with lower maintainability and more debt. [s12 ok] That is an association in people's answers, not a timed test of someone else changing the code. The review of the research counted the worry too: maintainability concerns came up in 11 of its sources, 23 percent. [s14 ok] That counts how often the concern is raised, which is not the same as measuring it. Then there is code out in the wild: a study that tracked commits made with AI coding assistants found that some of the issues they introduced still survive in the latest code. [s16 ok] The assistants fixed about as many code smells, surface problems like naming and formatting, as they introduced; but they introduced more correctness and security issues than they fixed. [s17 ok] But the authors did not compare those commits with code written by people alone, so the study cannot say AI code leaves more debt than human code does. [s18 ok] And the security worry? One study did put a number on it: of 733 code snippets generated by AI, 27.3 percent contained security weaknesses. [s30 ok] A newer audit went further: researchers sampled deployed web apps built at least 90 percent by AI agents, confirmed each finding by hand, and found at least one vulnerability in over 90 percent of them. [s34 ok] Both are counts of weaknesses in AI code alone; neither can tell you whether code written by hand would score any better on the same check. One study that did compare, in open-source repositories, found code written by AI agents introduced security findings at 1.14 times the rate of human code, line for line, and the most severe ones at 1.51 times, all flagged by an automated scanner rather than confirmed. [s35 ok] The review of the research found security risk was the challenge its sources raised most, in 10 of them, half of those it tallied for that question. [s19 ok] What those sources agree on is narrower than a rate: generated code may contain weaknesses when developers rely on it without rigorous checking. [s20 ok] There is one cost, though, that experiments did measure, and it lands on the person who wrote the code. In one trial, crowd workers recruited online, most of them freelance or professional software developers, did a coding task with or without AI, then took a quiz on the skills the task should have built. [s32 ok] Using AI did not make them significantly faster, and their scores came out lower by a gap worth 17 percent of the quiz. [s33 ok] In a separate experiment with different participants, working with AI cut their chance of answering questions about their own code correctly by 5.95 percentage points. [s22 ok] The authors re-checked it other ways: each time the drop kept its direction, though in one it was too weak to be sure of. [s23 ok]

## Answer

So, is AI-written code harder to maintain? In the one trial that tested it, over the time it ran, no: no reliable difference in speed or code health, though one trial with that much uncertainty cannot rule out a small one. [s24 ok] The louder maintenance warnings rest on questionnaires, counts of concern and issue tallies with nothing human to compare them to. Security is where the worry holds up: most of the AI-built apps that audit sampled had at least one vulnerability, and against human code the rate was higher, more so for the most severe findings. [s36 ok] The cost that was measured is different: in both of those experiments, people working with AI learned less or understood their own code less well, and whether that makes it harder for those same people to change their code later is something none of these studies tested. [s26 ok]

## Takeaway

Simon Willison draws his line here: "I don't think you should ever commit a line of code that a language model wrote If you don't understand it yourself". [s27 ok] So when you review AI-assisted code, yours or a colleague's, don't stop at whether it works: ask the author to walk you through it with the AI closed. If they can't, the code isn't finished yet.
