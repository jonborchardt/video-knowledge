# video-knowledge

Topic knowledge stores (claims from YouTube videos and blog posts, judged against studies) published as an Astro site. The workflow for adding a topic is in README.md; the agent contract for the watcher CLI is `.claude/skills/watcher/SKILL.md`; the briefs handed to parallel agents are `scripts/briefs/`.

## Commands

- `npm run validate` before committing: typecheck, lint, format check, build, tests. CI runs the same and deploys `dist/`.
- `npm run format` fixes formatting (prettier with astro + tailwind plugins).
- `npm run report` regenerates `<topic>/report.json`. It needs the watcher checkout (`../retire-sim/watcher` or `$WATCHER_DIR`), so it only runs locally; commit the result, the site is built from it.
- `npm run watcher -- <cmd> --store <topic>/store` runs the watcher CLI.
- `npm run stories -- discover <topic>` regenerates `<topic>/stories.json` (story candidates with their evidence audit), merging `<topic>/story-review.json` if present; it reads the report and store, so it runs anywhere. Commit the result. `validate <topic> <assertions.json>` is the evidence gate. The review file is the agent's semantic pass (`scripts/briefs/stories.md`): applicability of each verdict to a sentence, coherence and pruning of each candidate, viewer-facing framing.
- `npm run script -- run <topic> <story-id>` drives the script stage in `<topic>/scripts/<slug>/`: `package` builds the evidence package from stories.json and the store, `validate` checks `script.json` (written by an agent from `scripts/briefs/script.md`) and merges `script-review.json` (written by a different agent from `scripts/briefs/script-review.md`), `storyboard` fills and checks `storyboard.json` (from `scripts/briefs/storyboard.md`); `show` prints the reviewer's sheet; `lock --approved-by "<name>"` writes `release.json` (version 2) once validation is `passed`, the storyboard `ok` and `video/render-check.json` current with every graphic approved; it refuses a placeholder approver. Commit the directory.

- `npm run video -- spike <topic> <story-id>` renders `<topic>/scripts/<slug>/video/segment.mp4` from `video/render.json` (scenes, voice, cues, bespoke kinds, options, chapters): narrate (edge-tts draft or openai commercial, cached per sentence), timeline (measured audio, not the word-count estimate), render (Remotion, one cached chunk per scene, concatenated, narration track laid down with loudnorm, the soundtrack from `video/music.json` mixed under it into `video/mix.json`), qa (build-report.md, frames/, contact-sheet.png). `render --scene sc17` renders one scene with audio into `video/scenes/`. `package` writes the private review package to `video/review/`. `preview` opens the Remotion studio. Commit the JSON and the report, never the media.
- `npm run video -- init <topic> <story-id> [--force]` drafts `video/render.json` from the storyboard (never overwrites without `--force`); `check` writes `video/render-check.json` (renderability, diagrams without a graphic, each bespoke graphic's approval in `video/visual-review.json` at its key); `frames --scene <id>` renders one scene on its own into `video/frames/<id>-start|mid|end.png`. QA, spike and a full render end with `RESULT: PASSED` or `RESULT: FAILED (...)`.
- `npm run board -- next <topic> <story-id> [--json]` prints the board's stage, next step, steps and halt kind for one story; `.claude/skills/produce/SKILL.md` (`/produce`) loops on it from `ready` to `packaged`.
- `npm run music -- cues <topic> <story-id> [--composition <id>] [--force]` drafts `video/music.json` from the script's sections over a cleared composition.
- `npm run music -- import|render|show <composition>` keeps `music/<composition>/` (compositions rendered by strudel-bench; `music/README.md` is the contract, `scripts/briefs/strudel-bench.md` the handoff to that repo).

## Rules

- Never hand-edit `<topic>/store/` (`topics.json`, `videos/*.json`). Go through `npm run record`, `record-sources`, or the CLI. The agent batch formats (`h*.json`, `sv_*.json`) are typed and checked in `src/lib/batches.ts`; change the type, the check and the brief together.
- Evidence belongs to the claim, not the source. A verdict on a claim counts for every source that makes it. Adding a source never needs re-judging old claims.
- An AI guess counts for at most 0.5 confidence; a study verdict overrides it only when at least as confident.
- Canonical claim text: one line, mechanism-level, no numbers that belong to one source. No personal data in notes or claims; the store is public.
- `.claude/skills/watcher/SKILL.md` is a verbatim copy of `../retire-sim/watcher/SKILL.md`. Change it upstream and re-copy; don't edit it here.
- `stories.json` is derived: never hand-edit it, and never store passage text in it (references only; `show` re-reads passages). The validator in `src/lib/evidence.ts` must stay deterministic and fail closed; an AI guess never counts as verification; contextual evidence never decides. Semantic judgment lives only in `story-review.json`, keyed by stable ids, so runs stay reproducible. A story with more than one claim is never `ready` without a review.
- Script artifacts: the agent writes `script.json`, `script-review.json` and `storyboard.json`; everything else in `<topic>/scripts/<slug>/` is derived by the script-stage modules (`src/lib/evidence-package.ts`, `script-validation.ts`, `script-md.ts`, `release.ts`, with the shared types in `script.ts`) and `src/lib/storyboard.ts`, and is never hand-edited. The writer and the reviewer are different agents. A factual sentence needs an assertion per claim it makes; figures, quotations and calculations must trace to a cited passage; approvals are by fingerprint, so a changed sentence is re-reviewed. The storyboard never carries narration of its own; its chart data is numeric points with a unit and a cite (never prose values), its required assets are registered by id, and its timing is per sentence. Add passages to the corpus only through `record-sources` (a verdict on a claim), never by citing uncited lines.
- Video: `src/video/kinds.ts` is the closed map from storyboard scene to renderer, one `KindSpec` record per kind (component, accepted categories, inference, required cues, flags). Generic kinds there are inferred from category, chart type and assets; bespoke kinds are registered per video in `src/video/bespoke/` (keyed `<topic>/<story slug>`, names unique across videos), named per scene in that video's `render.json` and checked against the category. An unsupported scene fails the build, never a placeholder. `src/video/remotion/**`, `src/video/bespoke/**` and `types.ts`, `kinds.ts`, `words.ts`, `chart.ts`, `cues.ts`, `excerpt.ts` are browser-safe (no node imports). Cues name narration words in `render.json`; the timeline fails if the word is not spoken. Chart components read `chart.points`, text comes from `onScreenText`, excerpts from the cited passage; `options` carry layout choices only, never figures. A new component file goes in `COMPONENTS` (`remotion/scenes/index.ts`, keyed by its file name) so a kind can name it and the render cache sees its edits. Editing `Video.tsx` or another shared Remotion file invalidates every cached chunk.
- Soundtrack: `music/<composition>/composition.json` is written by `npm run music -- import`, never by hand except `licence.cleared`, `intensity` and `loop`, which it preserves; the WAVs are never committed. `video/music.json` holds cues over scene anchors, never seconds and never a composition; `video/mix.json` and `video/review/` are derived. Mixing is PCM in `src/video/mix.ts` (Remotion's ffmpeg has no afade, aloop or limiter), driven by `src/video/assemble.ts` (chunks, narration track, soundtrack, mux); `src/video/music.ts` is the contract only; the music is turned down to keep the peak under the ceiling, the narration never. The chunk cache key must stay ignorant of music, and only a full render mixes (a scene or range render is narration only). `mix.json` levels are as mixed, after the ceiling's scaling. A re-import keeps `cleared` only while the sound sources are unchanged. The review package refuses an mp4 whose sha is not the one the build report's QA checked. Narration licence and music clearance are recorded separately (one `clearance` in the build report, nowhere else) and a passing build never marks either cleared.
- Production: the board (`src/lib/production.ts`) is the state machine; every halt has a `kind` and the next step names a command or a brief, so `/produce` never parses prose. The `graphics` stage sits between `storyboard` and `lock` (releases without `version` are grandfathered). An automated lock is approved by `automated: /produce run started by <name>`. A writer pass has three revisions (`passStartRevision` starts a send-back pass; a `generation.corrective` entry is the only way past the limit); a writer that needs a passage sets `generation.needsEvidence` and stops. `record-sources` refuses to replace a verdict a script cites (same claim and document, another range) unless `--replace-cited`; `/produce` never passes it.
- Site pages are rendered at build time. Keep client JS to the tab bar, claim search and the board's Copy buttons.
- Find the repo root through `ROOT` in `src/lib/io.ts` (or a `root` argument defaulting to it), never `process.cwd()` or `import.meta.url`. File helpers (`sha`, `readJson`, `toJson`, ...) live there too; no stage imports another stage's module for a utility.
- The evidence gate and the script stage judge a `Corpus` (`src/lib/corpus.ts`), built from a `Topic` only by `corpusOf`; they never import `topics.ts`. The library layer never imports from `src/video/` (the board reads the build report through `BuildSummary` in `src/lib/build-report.ts`).
- Site name, nav, author and blog links live in `src/config/site.ts`. Build internal links with `href()` from `src/lib/url.ts` so they respect Astro's `base`.
